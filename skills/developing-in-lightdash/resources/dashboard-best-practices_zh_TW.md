# 儀表板最佳實踐 (Dashboard Best Practices)

本指南根據資料視覺化原則和商業智慧 (BI) 最佳實踐，引導您在 Lightdash 中建立高效且使用者友善的儀表板。

## 資料視覺化基礎

### 選擇正確的圖表類型

根據您要傳達的洞察類型選擇適合的視覺化方式：

| 洞察類型 | 建議圖表 | 應避免 |
|-------------|-------------------|-------|
| **隨時間變化的趨勢** | 摺線圖、面積圖 | 圓餅圖 |
| **比較** | 長條圖 (類別較多時使用橫向) | 過於擁擠的圖表 |
| **部分與整體的關係** | 圓餅圖/甜甜圈圖 (最多 5 個區段)、堆疊長條圖 | 過多區段 |
| **相關性** | 散佈圖 | 摺線圖 |
| **單一關鍵績效指標 (KPI)** | 大數字 (Big number) | 複雜圖表 |
| **詳細資料** | 表格 | 含有過多資料的圖表 |

### 視覺層級

1. **最重要的指標放在頂部**：使用者的閱讀習慣是從上到下、從左到右。
2. **KPI 先於細節**：先展示摘要指標，再展示支援性的圖表。
3. **關鍵洞察使用最大的圖塊**：大小代表了重要性。
4. **使用標題建立區塊**：引導讀者瀏覽整個故事。

### 保持簡單

- **每個檢視/分頁限制在 5-10 個圖表**：過多會造成認知負荷。
- **每個圖表只傳達一個洞察**：不要使用多個 Y 軸使其過於複雜。
- **移除無關的裝飾 (Chart Junk)**：避免使用不具意義的格線、邊框和裝飾。
- **使用一致的顏色**：相同的指標在所有圖表中應使用相同的顏色。

### 資料墨水比 (Data Ink Ratio)

最大化資料與非資料墨水的比例：

**應該做：**
- 移除不必要的格線
- 使用細微的座標軸線
- 讓資料成為主角

**不該做：**
- 在圖表周圍添加沉重的邊框
- 使用漸層填充
- 包含裝飾性圖像

## 儀表板版面原則

### 倒金字塔結構

像新聞報導一樣建構儀表板：

1. **頂部**：關鍵 KPI 和標題 (大數字)。
2. **中部**：支援性的趨勢和分解 (圖表)。
3. **底部**：詳細資料和下鑽分析 (表格)。

### 常見版面模式

**高階主管儀表板 (Executive Dashboard)：**
```
┌─────────────────────────────────────────────┐
│  KPI  │  KPI  │  KPI  │  KPI  │  (寬度各為 9)
├───────────────────────┬─────────────────────┤
│   主要趨勢圖          │   關鍵洞察          │
│      (寬: 24)         │     (寬: 12)        │
├───────────────────────┴─────────────────────┤
│           支援圖表/表格                     │
│                  (寬: 36)                   │
└─────────────────────────────────────────────┘
```

**營運儀表板 (Operational Dashboard)：**
```
┌─────────────────────────────────────────────┐
│              篩選列 (Filters Bar)           │
├─────────────────────────────────────────────┤
│  狀態 KPI   │ 狀態 KPI   │ 狀態 KPI         │
├─────────────────────────────────────────────┤
│           即時/近期資料表格                 │
├─────────────────────────────────────────────┤
│   趨勢 1     │   趨勢 2     │   趨勢 3     │
└─────────────────────────────────────────────┘
```

**分析儀表板 (Analytical Dashboard)：**
```
┌─────────────────────────────────────────────┐
│              摘要指標                       │
├─────────────────────────────────────────────┤
│         主要分析圖表                        │
├──────────────────────┬──────────────────────┤
│   分解分析 1         │    分解分析 2        │
├──────────────────────┴──────────────────────┤
│           詳細資料表格                      │
└─────────────────────────────────────────────┘
```

## Lightdash 特有的最佳實踐

### 有效使用分頁 (Tabs)

分頁有助於組織複雜的儀表板，而不會讓使用者感到不知所措：

```yaml
tabs:
  - uuid: "overview"
    name: "總覽"          # 從高階視角開始
    order: 0
  - uuid: "trends"
    name: "趨勢"          # 基於時間的分析
    order: 1
  - uuid: "breakdown"
    name: "分解"          # 維度分析
    order: 2
  - uuid: "details"
    name: "詳情"          # 詳細資料表格
    order: 3
```

**何時使用分頁：**
- 儀表板有超過 8-10 個圖塊。
- 內容可以自然地按主題分組。
- 不同的受眾需要不同的視角。
- 分析流程從摘要到細節。

**分頁命名建議：**
- 保持名稱簡短 (1-2 個詞)。
- 使用名詞而非動詞 (例如「總覽」而非「查看總覽」)。
- 邏輯排序 (一般 → 具體)。

### 使用標題進行組織

標題可在分頁內建立視覺區塊：

```yaml
tiles:
  - type: heading
    x: 0
    y: 0
    w: 36
    h: 1
    properties:
      text: "營收績效"

  # 下方為營收圖表...

  - type: heading
    x: 0
    y: 8
    w: 36
    h: 1
    properties:
      text: "客戶指標"

  # 下方為客戶圖表...
```

**何時使用標題：**
- 在分頁內分組相關圖表。
- 分隔邏輯區段。
- 建立類似目錄的感覺。

### 使用 Markdown 圖塊

Markdown 圖塊可增加背景資訊、說明和指引：

**Markdown 的用途：**
- 說明儀表板顯示的內容。
- 強調關鍵洞察。
- 提供解讀指引。
- 添加指向相關資源的連結。
- 記錄資料來源或注意事項。

```yaml
- type: markdown
  x: 24
  y: 0
  w: 12
  h: 6
  properties:
    title: "關於此儀表板"
    content: |
      ## 目的

      此儀表板追蹤**每週銷售績效**與目標的對比。

      ## 關鍵指標

      - **營收 (Revenue)**：總發票金額
      - **管線 (Pipeline)**：加權後的機會價值

      ## 資料新鮮度

      每 4 小時從 Salesforce 更新一次。

      ---

      有問題嗎？請聯繫 [analytics@company.com](mailto:analytics@company.com)
```

**Markdown 使用建議：**
- 不要過度使用：保持說明簡潔。
- 使用格式：粗體用於強調，標題用於結構。
- 包含連結：指向文件、相關儀表板或聯繫人。
- 對於冗長的說明，考慮使用可摺疊區塊。

**Markdown 中的豐富 HTML：**
Lightdash 支援在 Markdown 中使用 HTML 進行進階格式化：

```yaml
content: |
  <div style="background: #f0f9ff; padding: 16px; border-radius: 8px;">
    <strong>注意：</strong> 第四季資料包含 12 月的預估值。
  </div>
```

### 篩選器最佳實踐

#### 選擇適當的篩選器預設值

沒有預設值的篩選器 (`values: []`) 表示「任何值」——篩選器可見但未套用。這對於使用者可以選擇性套用而不影響初始儀表板視圖的**建議篩選器**非常有用。

當篩選器在載入時**應該處於活動狀態**時，使用帶有預設值的篩選器會更好：

```yaml
filters:
  dimensions:
    # 帶有預設值的篩選器 - 載入時即生效
    - target:
        fieldId: orders_created_at
        tableName: orders
      operator: inThePast
      values: [90]              # 預設：過去 90 天
      settings:
        unitOfTime: days
        completed: false
      label: "日期範圍"

    # 不帶預設值的篩選器 - 僅供建議，未套用
    - target:
        fieldId: orders_region
        tableName: orders
      operator: equals
      values: []                # 無預設值 = 顯示所有區域
      label: "區域"
```

**何時使用預設值：**
- 應該限制資料的時間篩選器 (例如：過去 90 天)。
- 您希望預設顯示活動/開啟項目的狀態篩選器。
- 任何能顯著改善初始視圖的篩選器。

**何時省略預設值：**
- 使用者可能想要但非必要的建議篩選器。
- 「全部」是合理起點的篩選器。
- 使用者應自行選擇範圍的探索型儀表板。

**提示：** 優先選擇具有合理預設值的篩選器，而不是沒有值的必填篩選器——立即顯示資料比強制使用者選擇能提供更好的使用者體驗。

#### 在適當的時候使用必填篩選器

必填篩選器確保儀表板僅在提供背景資訊時才顯示：

```yaml
filters:
  dimensions:
    - target:
        fieldId: customers_account_id
        tableName: customers
      operator: equals
      values: []
      required: true           # 使用者必須選擇
      label: "選擇帳戶"
```

**何時需要必填篩選器：**
- 儀表板僅在特定背景下才有意義 (例如：特定帳戶、區域)。
- 未經篩選時資料量過大。
- 安全性/隱私要求明確選擇。

#### 限制篩選器數量

- 3-5 個主要篩選器最為理想。
- 過多篩選器會讓使用者感到困惑。
- 使用分頁來分隔不同的篩選器背景。
- 考慮哪些篩選器適用於所有圖表，哪些僅適用於特定圖塊。

### 內容組織技巧

#### 說一個故事

建構儀表板以按順序回答問題：

1. **發生了什麼事？** (KPI、摘要指標)
2. **為什麼會發生？** (分解分析、趨勢)
3. **我們該怎麼做？** (Markdown 中的洞察、建議)
4. **細節是什麼？** (用於下鑽分析的表格)

#### 為您的受眾設計

| 受眾 | 關注點 | 應避免 |
|----------|----------|-------|
| **高階主管** | KPI、趨勢、摘要 | 技術細節、過多圖表 |
| **分析師** | 分解、篩選器、下鑽分析 | 過度簡化 |
| **營運人員** | 當前狀態、異常、行動 | 歷史趨勢 |
| **自助式使用者** | 清晰的標籤、說明 | 術語、假設已知知識 |

#### 保持一致性

- **相同的指標，相同的名稱**：不要在一個地方稱之為「營收」，在另一個地方稱之為「銷售額」。
- **相同的配色方案**：在不同圖表中對相同的維度使用一致的顏色。
- **相同的時間粒度**：如果一個圖表顯示月度資料，不要在沒有說明的情況下混入日資料。
- **相同的篩選器**：儀表板篩選器應一致地套用 (例外情況請使用 `tileTargets`)。

## 效能考量

### 優化載入時間

1. **限制圖塊數量**：每個圖塊都是一個查詢。
2. **使用適當的限制**：圖表不要返回 10,000 列資料。
3. **在模型中預先篩選**：移除無關的歷史資料。
4. **使用分頁**：初始僅執行可見分頁的查詢。

### 查詢效率

- **避免 SELECT ***：僅包含需要的維度和指標。
- **使用日期篩選器**：限定時間範圍的查詢速度更快。
- **考慮聚合**：在 dbt 中為常見視圖預先聚合資料。

## 應避免的常見錯誤

### 版面錯誤

- **全寬使用 w: 24 或更小**：網格共有 36 欄，請使用 `w: 36`。
- **過於擁擠**：保留視覺上的呼吸空間。
- **高度不一致**：同一水平線上的圖表應具有相同高度。
- **行動裝置體驗不佳**：在較小螢幕上進行測試。

### 視覺化錯誤

- **圓餅圖區段過多**：最多 5 個，否則請使用長條圖。
- **截斷 Y 軸**：可能會誇大微小的變化。
- **缺乏背景資訊**：沒有比較的數字是沒有意義的。
- **雙 Y 軸**：難以解讀，請使用分開的圖表。

### 內容錯誤

- **缺乏說明**：使用者不應猜測指標的含義。
- **資料過時且無標示**：顯示資料新鮮度。
- **缺少時間篩選器預設值**：在應套用日期範圍時，儀表板載入了過多資料。
- **混合受眾**：將主管摘要與分析師深挖放在一起。

## 儀表板檢查清單

發佈前，請確認：

- [ ] KPI 位於頂部
- [ ] 圖表類型與資料/洞察匹配
- [ ] 應處於活動狀態的篩選器具有合理的預設值
- [ ] 必填篩選器已在需要處設定
- [ ] 若圖塊超過 10 個，已使用分頁
- [ ] 標題分隔了邏輯區段
- [ ] Markdown 說明了目的和關鍵洞察
- [ ] 不同圖表的顏色保持一致
- [ ] 在適當處使用了全寬 (w: 36)
- [ ] 儀表板在合理時間內載入
- [ ] 可在不同螢幕尺寸下運作
- [ ] 所有圖表皆有清晰標題
- [ ] 若相關，已標示資料新鮮度
